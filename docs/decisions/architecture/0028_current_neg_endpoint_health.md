# Current NEG endpoint health verification

The production preflight requires positive load-balancer health evidence for the current relay pod. Its original path still requires the exact positive controller condition for the current NEG, zone, and backend. A generic Pod Ready condition or healthy aggregate backend is insufficient.

GKE's readiness reflector can instead record `LoadBalancerNegWithoutHealthCheck` when a newly registered endpoint has no reported health check yet. The [upstream poller](https://github.com/kubernetes/ingress-gce/blob/master/pkg/neg/readiness/poller.go) passes that observation to the [reflector](https://github.com/kubernetes/ingress-gce/blob/master/pkg/neg/readiness/reflector.go), which can stop processing once the condition is True. The recorded reason therefore does not establish the endpoint's current health. Waiting for that reason to change is not a reliable verification strategy.

Only that recognized historical branch can use a direct read. The preflight first requires the exact no-health-check message for a current Service-declared NEG zone, the expected rollout, complete ready endpoint membership, the current Ingress route, and disabled BackendConfig logging. It then runs the captured, time-bounded [`gcloud compute backend-services get-health`](https://cloud.google.com/sdk/gcloud/reference/compute/backend-services/get-health) command for the one namespace-derived global backend in the configured project. No broad inventory or IAM change is performed. The [API requires `compute.backendServices.get`](https://cloud.google.com/compute/docs/reference/rest/v1/backendServices/getHealth); unavailable existing permission remains a failed check.

The response must contain exactly the Service-declared zonal groups. Exactly one endpoint, in the historical message's zone, must report `HEALTHY` for the sole current pod's IPv4 address and port 8080, with its exact node instance, project, zone, and NEG. Other declared zones must be empty. Missing, duplicated, foreign, unhealthy, ambiguous, or unsupported IPv6 data cannot satisfy the check. The SDK returns a nonzero exit status for partial group-read errors; captured errors are reported only through fixed categories.

After the health read, the preflight rereads the relay Deployment, Service, Ingress, BackendConfig, pods, EndpointSlices, and core Endpoints. It revalidates readiness and membership and compares object UIDs, routing/configuration, and pod identity with the original snapshot. A replacement or relevant change fails closed. This detects changes between these reads; it does not claim an atomic cluster/cloud snapshot or guarantee future health.

All other required topology, image, public-version, and proxy checks remain in place. Diagnostics identify the direct health result separately; they never relabel the historical condition as a positive controller observation. This verification change does not rebuild or replace existing release artifacts or redeploy the application.
