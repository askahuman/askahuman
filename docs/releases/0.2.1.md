# 0.2.1 upgrade and iPhone checks

Version 0.2.1 prevents Enter from sending a reply or starting pairing while an input-method editor (IME) is composing text. Ordinary Enter and the explicit buttons still submit completed input. The guided iPhone test now supplies a single-line long reply, matching the control's existing behavior. Protocol v2 is unchanged from 0.2.0.

## Upgrade

1. Finish or cancel pending requests. Download the [v0.2.1 GitHub release](https://github.com/askahuman/askahuman/releases/tag/v0.2.1) archive for your OS (`darwin`, `linux`, or `windows`) and CPU (`arm64` or `amd64`), plus `checksums.txt` and `checksums.txt.sigstore.json`. [Verify the signed checksums](../decisions/architecture/0017_release_signing_keyless.md) with `VERSION=0.2.1`, compare the archive's SHA-256 with its checksum entry, and extract it. This path does not require npm.
2. Run the extracted binary (`ask-a-human`, or `ask-a-human.exe` on Windows) to check the exact release:

   ```sh
   "/absolute/path/to/ask-a-human" version --json
   ```

   Expect version `0.2.1` and commit `b9df26fc8fb1b1d80c1559089a5558f492164584`.
3. Set your MCP client's command to the binary's absolute path, with arguments `["serve"]` and any existing relay/name flags. [Codex uses a TOML entry or `codex mcp add`](../../README.md#codex); Cursor and Claude Desktop use JSON. Restart that MCP server.
4. Open the phone app online, close it, and reopen it so the service-worker update takes effect. In **Add agent**, verify the footer shows `0.2.1` and `b9df26f`. Self-hosters must deploy their matching web and relay builds first.
5. Upgrading from 0.1.x requires protocol v2 on both sides and fresh pairings; old pairings cannot approve. Upgrading from 0.2.0 does not change the protocol, but restarting the local MCP process loses its pairing keys. Call `start_pairing` with `{"reset":true}` on each restarted agent, enter its fresh local code in the phone, and remove obsolete entries after the replacement works. Keep codes out of chat and shared screenshots.

**Optional npm setup:** First check `npm view @askahuman/mcp@0.2.1 version`. Only if it returns `0.2.1`, you can use command `npx` and arguments `["-y", "@askahuman/mcp@0.2.1", "serve"]` instead of the binary path. Verify it with `npx -y @askahuman/mcp@0.2.1 version --json`, then continue at step 4. If the version is absent, keep using the verified GitHub binary; 0.1.x packages cannot pair with the protocol-v2 phone app.

## Physical iPhone acceptance

Follow the [shared physical checklist](0.2.0.md#physical-iphone-acceptance), using version `0.2.1` and its full commit for the guided driver:

```sh
node scripts/iphone_acceptance.mjs /absolute/path/to/ask-a-human 0.2.1 FULL_40_CHARACTER_COMMIT
```

Use the complete single-line long reply supplied by the driver. It may wrap visually; do not insert line breaks. Confirm its exact returned text, final marker, retained receipt, and Done action.

If a composing keyboard such as Japanese or Chinese is already available, also send a separate harmless text request. Compose a word and press Return to accept the candidate: the question must remain unanswered. Finish the reply, then tap Send or press Return again; only that action should produce the verified receipt. This optional check does not require installing a keyboard.

Record the iOS version, app version/commit, and any failing step using synthetic content only. Browser regression tests do not certify physical iPhone notification delivery or every installed keyboard.
