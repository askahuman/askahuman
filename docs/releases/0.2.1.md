# 0.2.1 upgrade and iPhone checks

Version 0.2.1 prevents Enter from sending a reply while an input-method editor (IME) is composing text. Ordinary Enter and the Send button still send the completed single-line reply. The guided iPhone test now supplies a single-line long reply, matching the control's existing behavior. Protocol v2 is unchanged from 0.2.0.

## Upgrade

1. Finish or cancel pending requests. Set your MCP client's command to `npx` and its arguments to `["-y", "@askahuman/mcp@0.2.1", "serve"]`, preserving any existing relay/name flags. Restart that MCP server. Check the exact release separately:

   ```sh
   npx -y @askahuman/mcp@0.2.1 version --json
   ```

   Expect version `0.2.1`. Record the full 40-character commit returned by this command and compare it with the [v0.2.1 release tag](https://github.com/askahuman/askahuman/releases/tag/v0.2.1).
2. Open the phone app online, close it, and reopen it so the service-worker update takes effect. In **Add agent**, verify the footer shows `0.2.1` and the same short commit. Self-hosters must deploy their matching web and relay builds first.
3. Upgrading from 0.1.x requires protocol v2 on both sides and fresh pairings; old pairings cannot approve. Upgrading from 0.2.0 does not change the protocol, but restarting the local MCP process loses its pairing keys. Call `start_pairing` with `{"reset":true}` on each restarted agent, enter its fresh local code in the phone, and remove obsolete entries after the replacement works. Keep codes out of chat and shared screenshots.

If npm does not yet provide `@askahuman/mcp@0.2.1`, use the [GitHub release](https://github.com/askahuman/askahuman/releases/tag/v0.2.1). Download the archive for your OS (`darwin`, `linux`, or `windows`) and CPU (`arm64` or `amd64`), plus `checksums.txt` and `checksums.txt.sigstore.json`. [Verify the signed checksums](../decisions/architecture/0017_release_signing_keyless.md) with `VERSION=0.2.1`, compare the archive's SHA-256 with its checksum entry, and extract it. Set the MCP client's command to the extracted binary's absolute path (`ask-a-human`, or `ask-a-human.exe` on Windows), with arguments `["serve"]` and any existing relay/name flags. Run that binary with `version --json`, verify version `0.2.1` and the release's full commit, then continue at step 2 above. This path does not require npm.

## Physical iPhone acceptance

Follow the [shared physical checklist](0.2.0.md#physical-iphone-acceptance), using version `0.2.1` and its full commit for the guided driver:

```sh
node scripts/iphone_acceptance.mjs /absolute/path/to/ask-a-human 0.2.1 FULL_40_CHARACTER_COMMIT
```

Use the complete single-line long reply supplied by the driver. It may wrap visually; do not insert line breaks. Confirm its exact returned text, final marker, retained receipt, and Done action.

If a composing keyboard such as Japanese or Chinese is already available, also send a separate harmless text request. Compose a word and press Return to accept the candidate: the question must remain unanswered. Finish the reply, then tap Send or press Return again; only that action should produce the verified receipt. This optional check does not require installing a keyboard.

Record the iOS version, app version/commit, and any failing step using synthetic content only. Browser regression tests do not certify physical iPhone notification delivery or every installed keyboard.
